# МП Управляющий — модуль владельца

Первая версия защищённой панели для проекта «Выход на маркетплейсы». Веб-приложение на Node.js 24, без дополнительной базы и без сторонних npm-зависимостей. Разработано поверх существующих файлов проекта \`/home/deploy/МП Выход\`, НЕ вместо уже работающего «Потока» или репрайсера.

**Состояние:** исходный код модуля и тесты готовы в ветке GitHub; пока не установлен на сервер и не проверен реальный ответ API Ozon. Не выдавайте разработанную программу за подключённый магазин.

## Возможности

- Авторизация администратора по защищённой cookie, срок сеанса 12 часов; пароль читается только из отдельного файла с правами 0600, в логи и браузер не передаётся.
- Адаптивный интерфейс (компьютер / телефон): обзор, товары из 1С, карточки сайта, экономика, реклама, ролевые ИИ-агенты, подключения.
- Чтение сохранённых CSV/JSON-подготовительных данных из проекта без пересчёта и без записи в 1С; вывод метки устаревшего среза.
- 16 выбранных товаров Stolberi, локальные фотографии, Ozon/WB-черновики и блокеры карточек.
- Отметки «согласовать текст», «на доработку», «сбросить» хранятся в \`manager-approvals.json\`. Это только внутренняя оценка черновика; никакой публикации.
- Безопасный тест Ozon Seller API: \`POST /v3/product/list\` (чтение первой страницы до 100 товаров). Client ID и ключ читаются только на сервере. Никакой отправки товаров, цен, рекламы или заказов нет.
- Если сайт и 1С не сопоставлены однозначно, себестоимость и остатки отображаются как «не подтверждены». Никаких фиктивных значений.

## Прежде чем развернуть

Установить Node.js 24 на Ubuntu. Проект \`/home/deploy/МП Выход\` должен существовать и быть доступен пользователю процесса. Подготовить пароль администратора отдельным файлом с правами 0600, а ключ Ozon — отдельным секретным файлом 0600. **Не публикуйте секреты в GitHub и не копируйте их в чат.**

Пример установки из чистой копии ветки (подставить свои URL/домены):

\`\`\`bash
# пример: код уже размещён в /opt/marketflow (включая папку manager)
sudo install -d -m 0700 -o deploy -g deploy /home/deploy/.config/mp-manager
sudo -u deploy sh -c 'umask 077; read -r -s -p "Пароль МП Управляющего: " p; printf "\n"; printf "%s\n" "$p" > /home/deploy/.config/mp-manager/password'
# API-ключ из личного кабинета помещается отдельно в /home/deploy/.config/mp-manager/ozon-api-key, не через командную строку
chmod 600 /home/deploy/.config/mp-manager/password /home/deploy/.config/mp-manager/ozon-api-key

MP_PROJECT_DIR='/home/deploy/МП Выход' \
MP_PUBLIC_ORIGIN='https://mp.example.ru' \
MP_PORT='8777' \
MP_ADMIN_PASSWORD_FILE='/home/deploy/.config/mp-manager/password' \
OZON_CLIENT_ID='6241845' \
OZON_API_KEY_FILE='/home/deploy/.config/mp-manager/ozon-api-key' \
node /opt/marketflow/manager/server.mjs
\`\`\`

Для первого просмотра без реального API допускается не задавать \`OZON_API_KEY_FILE\`; интерфейс будет работать на локальных данных, а кнопка проверки вернёт статус «не настроено».

Пароль должен быть длиной не менее 16 символов. Пароль запрещено записывать в историю shell, переменные CI/CD, URL или GitHub. Если секрет уже находился в обычном документе или попадал в историю коммитов, **выпустите новый Ozon API-ключ** перед боевым подключением.

Приложение слушает **127.0.0.1:8777**, не открывает порт всему интернету. HTTPS и домен настраиваются через существующий обратный прокси на сервере (Caddy/Nginx) так, чтобы заголовок \`Host\` и \`Origin\` соответствовали значению \`MP_PUBLIC_ORIGIN\`. Никогда не использовать его по публичному HTTP. Рекомендуется отдельный subdomain \`mp.*\` и отдельная служба systemd с доступом к секретным файлам только у пользователя сервиса.

\`GET /healthz\` — техническая проверка без секретов. \`GET /api/snapshot\`, \`POST /api/ozon/check\`, \`POST /api/approvals\` требуют авторизации, POST дополнительно требует совпадения Origin. Фото доступны только авторизованному пользователю и только по допустимым именам.

## Тесты

\`\`\`bash
node --check manager/core.mjs
node --check manager/server.mjs
node --check manager/web/app.js
node --test manager/manager.test.mjs
\`\`\`

Тесты используют временные файлы и имитированный ответ API: **реальный Ozon в тестах не вызывается**.

## Дальнейшее развитие

1. Установить модуль под отдельным URL, получить успешный read-only ответ Ozon.
2. Сопоставить товары сайта с каталогом 1С; для комплектующих построить BOM/комплектацию.
3. Подтвердить реальные остатки, документы ТР ТС и тарифы, рассчитать прибыль.
4. После персонального утверждения подключить загрузку карточек, заказы, остатки и рекламный API.
5. Интегрировать работающий репрайсер и «Поток» через серверные адаптеры с журналом операций и лимитами.

**Не реализовано в первой версии:** автопилот агентов, фактические рекламные метрики, синхронизация остатков в реальном времени, публикации, изменение цен, запись в 1С, работа с Wildberries API. Эти операции не должны маркироваться в UI как действующие.
