# Поток — единый кабинет заказов Ozon и Wildberries

Приватное веб-приложение для просмотра заказов, локальной сборки FBS и подготовки этикеток. Поддерживаются Ozon FBS/FBO и Wildberries FBS/FBW. Демонстрационный режим работает без ключей маркетплейсов.

Рабочая приватная версия: https://marketflow-dmitry-orders.nearbolt.chatgpt.site — доступ владельцу через ChatGPT. Репозиторий содержит исходники и самостоятельную серверную сборку. GitHub Pages не выполняет сервер Node.js и не заменяет сервер с базой данных.

## Возможности

- Единый список, поиск, фильтры по площадке, схеме и этапу, карточка заказа с несколькими товарами.
- CSV/JSON с предварительной проверкой; повторный импорт без дубликатов, с сохранением локального этапа.
- FBS: новый → сборка → готов к отгрузке; в демо также моделируется передача. FBO/FBW обрабатывает маркетплейс.
- Векторные Code 128, предпросмотр, 58×40 мм, 100×150 мм и A4, системный диалог печати и сохранение PDF. Внутренние и демо-этикетки явно помечены.
- Серверная SQLite-база, журнал, независимые сессии разных устройств; открытые вкладки обновляются каждые 10 секунд и при возвращении фокуса.
- Защищённый вход: scrypt-хеш пароля, HttpOnly-cookie, хеши серверных сессий, ограничение неверных входов и проверка Origin.
- API-ключи вводятся в форме приложения, шифруются AES-256-GCM и не возвращаются клиенту. Синхронизация и запрос официальной этикетки требуют подтверждения.

## Архитектура

React/Vite → HTTP-сервер Node.js 24 → SQLite WAL. Серверные адаптеры и правила обработки общие с версией для Sites. Сборка `selfhost/build.mjs` формирует готовый клиент, сервер, миграции и установщик в `work/selfhost-release/`.

Один приватный кабинет владельца доступен с разных устройств. Отдельные роли сотрудников в v1 не реализованы. Серверная версия не доверяет присланным клиентом заголовкам идентификации.

## Проверка и сборка

Требуются Node.js 24.12+ и pnpm 11.25.0.

```sh
pnpm install --frozen-lockfile
pnpm typecheck
pnpm test
```

`pnpm test` выполняет 34 проверки: 10 основных, 8 API, 11 интеграционных сценариев самостоятельного сервера и 5 сценариев развёртывания. Проверяются две независимые сессии, общая база, повторный импорт, сохранение после перезапуска, выход, смена пароля, шифрование, обязательная проверка SSH-ключа сервера, очистка временных ключей и обработка сбоев установки. Реальные ключи, SSH-серверы и аккаунты маркетплейсов в тестах не используются.

Автоматическая проверка: `.github/workflows/ci.yml`. После успешного запуска в Actions доступен артефакт `marketflow-ubuntu` с архивом для установки. Архив содержит программу без рабочих данных и ключей. Результат конкретного запуска смотрите в Actions.

## Установка через GitHub — без ChatGPT

Добавлен ручной workflow **Install Marketflow on Ubuntu**. Он проверяет приложение, устанавливает его по SSH на ваш сервер и проверяет HTTPS-форму входа и защиту API. Кабинет использует собственные логин и пароль, а данные хранятся на сервере.

Нужны свой домен с DNS на сервер и четыре настройки в GitHub Secrets: `SERVER_HOST`, `SERVER_PASSWORD` (либо `SERVER_SSH_KEY`), `SERVER_KNOWN_HOSTS`, `CABINET_PASSWORD`. Не присылайте секреты в чат. Код не содержит адреса сервера и паролей.

[Пошаговая настройка и запуск через GitHub Actions](selfhost/deploy/GITHUB-ACTIONS-RU.md).

Установка запускается только через **Actions → Install Marketflow on Ubuntu → Run workflow**, из ветки `main` и с подтверждением `INSTALL`. Push и PR не запускают установку. Существующий серверный кабинет не перезаписывается. Пока секреты не добавлены и workflow не запущен, сервер не установлен, а прежний адрес Sites по-прежнему использует вход через ChatGPT.

## Установка на Ubuntu

Подробная инструкция: [selfhost/deploy/README-RU.md](selfhost/deploy/README-RU.md).

1. Соберите пакет командой `pnpm build` или скачайте артефакт успешного запуска Actions.
2. Передайте готовый пакет на свой сервер.
3. Установите базовые зависимости Ubuntu: `curl`, `ca-certificates`, `python3`, `xz-utils`.
4. Запустите `bash install.sh` в распакованной папке. Пароль кабинета задаётся скрыто в терминале, не в аргументах команды.

Без домена приложение слушает только `127.0.0.1:3000`; вход осуществляется через SSH-туннель. Для HTTPS укажите свой домен:

```sh
bash install.sh --domain orders.example.com --username dmitry
```

Замените домен своим и направьте его DNS на сервер. Установщик поддерживает Caddy, если существующий веб-сервер не занимает порты. При занятом порте или существующей установке он останавливается без перезаписи. Серверная сборка не зависит от входа через ChatGPT.

## Данные и секреты

- База: `/var/lib/marketflow/orders.sqlite3`.
- Закрытая конфигурация: `/var/lib/marketflow/config.json`, права 0600. Содержит мастер-ключ и хеш пароля; не включайте её в Git, issues, артефакты CI или чат.
- Программа: `/opt/marketflow/app`; сервис: `marketflow.service`.
- Резервная копия: `backup.sh` из пакета. Используется SQLite backup API; копия включает ключ шифрования и должна храниться как секрет.
- Репозиторий и CI не содержат рабочих данных или ключей. Мастер-ключ и пароль создаются на сервере.
- Перенос данных между Sites и сервером не автоматический. Заказы можно перенести через CSV; история и этапы требуют отдельного переноса.

## Границы v1

Реальная упаковка Ozon, создание и закрытие поставок WB, реальная отгрузка, отмены, возвраты, Честный знак и синхронизация остатков пока выполняются в кабинетах площадок. Этап сборки здесь локальный; статус маркетплейса показывается отдельно.

API-адаптеры **не проверены с реальными ключами продавца**. Доступы, актуальные контракты и официальные этикетки следует проверить отдельно перед эксплуатацией. Ozon: заказы за 7 дней, до 1000 записей на синхронизацию. WB FBS: новые сборочные задания; WB FBW: отчёт за 7 дней, который может поступать с задержкой.

Аппаратная печать на конкретной модели принтера не тестировалась. Сначала выполните пробную печать в масштабе 100%.
