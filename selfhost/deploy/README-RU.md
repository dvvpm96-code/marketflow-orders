# Поток — установка на свой сервер

Пакет предназначен для Ubuntu 26.04 с systemd (amd64/arm64). Установка на сервер в этой сессии не выполнена: исходящее SSH-соединение из среды помощника завершилось `Network is unreachable` до аутентификации. Пакет содержит собранный интерфейс и сервер, а не исходники для компиляции на сервере. Для запуска нужен Node.js 24; установщик загружает отдельный runtime 24.22.2 с nodejs.org и проверяет SHA-256. Серверу нужны curl, ca-certificates, python3, xz-utils, доступ в интернет по HTTPS. Установщик не изменяет SSH, firewall, существующий веб-сервер или старую установку «Потока».

## 1. Перенести пакет

Скачайте `marketflow-ubuntu.tar.gz` на компьютер. В терминале, находясь в папке скачанного файла:

```sh
scp marketflow-ubuntu.tar.gz root@SERVER_IP:/root/
ssh root@SERVER_IP
mkdir -p /root/marketflow-ubuntu
tar -xzf /root/marketflow-ubuntu.tar.gz -C /root/marketflow-ubuntu
cd /root/marketflow-ubuntu
bash install.sh --dry-run
```

SSH-пароль вводится только в вашем терминале. Никому не передавайте закрытый SSH-ключ.

## 2. Выбрать способ доступа

**Есть свой домен** (например `orders.example.ru`): сначала направьте его DNS A-запись на `SERVER_IP`. Затем:

```sh
bash install.sh --domain orders.example.ru --username dmitry
```

Во время установки задайте пароль не короче 12 символов. Он вводится скрыто, не передаётся в аргументах и не печатается. Установщик сохранит только scrypt-хеш. Секрет шифрования API-ключей создаётся прямо на вашем сервере.

Установщик добавит отдельный непривилегированный сервис `marketflow`, установит Caddy из репозитория Ubuntu и настроит HTTPS. Если Caddy уже установлен либо заняты порты 80/443, установщик остановится до изменений: для защиты существующих сайтов настройте ваш текущий reverse proxy. В Caddy достаточно блока:

```caddy
orders.example.ru {
    reverse_proxy 127.0.0.1:3000
}
```

В конфигурации `/var/lib/marketflow/config.json` origin должен точно совпадать с `https://orders.example.ru`. Изменить его без раскрытия ключей:

```sh
/opt/marketflow/runtime/bin/node /opt/marketflow/app/server/admin.mjs origin /var/lib/marketflow/config.json https://orders.example.ru
chown marketflow:marketflow /var/lib/marketflow/config.json
systemctl restart marketflow
```

Порты 80/443 должны быть доступны, DNS A/AAAA не должен указывать на другие машины. После выдачи сертификата открывайте HTTPS-адрес с компьютера, телефона или планшета. На каждом устройстве можно войти теми же логином и паролем: сессии независимы, база общая. Незалогиненный посетитель видит только форму входа. Приложение не публикуется как открытый кабинет. Сертификаты домена могут отражаться в публичных журналах сертификатов.

**Домена пока нет**: запустите:

```sh
bash install.sh --username dmitry
```

Сервис будет доступен только на `127.0.0.1:3000` сервера. На каждом устройстве создайте SSH-туннель; на компьютере:

```sh
ssh -N -L 8080:127.0.0.1:3000 root@SERVER_IP
```

Оставьте этот терминал открытым и откройте `http://localhost:8080`. Данные передаются внутри SSH-туннеля. Для телефона потребуются SSH-клиент с перенаправлением портов либо домен с HTTPS. Не открывайте порт 3000 в интернет и не вводите пароль на HTTP-адресе сервера.

## Данные и доступ

- Рабочая база: `/var/lib/marketflow/orders.sqlite3`, SQLite WAL. Заказы, этапы, события, зашифрованные API-ключи и серверные сессии хранятся постоянно, отдельно от программы.
- Секреты: `/var/lib/marketflow/config.json`, права 0600. Файл содержит мастер-ключ AES-GCM и хеш пароля; не отправляйте его в чат, Git или публичное хранилище.
- Один приватный кабинет владельца. Это вход с разных устройств одного владельца; отдельные роли сотрудников в эту версию не входят.
- Сессия — 7 дней, cookie HttpOnly и SameSite=Strict, Secure при HTTPS; в базе хранится SHA-256 токена. Выход завершает только текущую сессию.
- Восемь неверных входов за 15 минут ограничивают следующие попытки. За reverse proxy лимит общий для прокси — не зависит от подделываемого клиентом заголовка.
- Сервер игнорирует присланные пользователем identity-заголовки ChatGPT. Идентификация производится только по серверной сессии.
- Открытые видимые вкладки обновляют локальные данные каждые 10 секунд и при возвращении фокуса. Это чтение вашей базы; автоматических запросов к маркетплейсам нет.
- Ограничения v1 сохранены: реальные упаковка, поставки и отгрузка выполняются в кабинетах площадок. API-адаптеры не проверены с реальными ключами пользователя.

**Данные из Sites автоматически не переносятся.** Текущий приватный Site продолжает работать отдельно. Для переноса заказов используйте экспорт CSV в Sites и импорт на сервере; этапы/журнал требуют отдельного контролируемого переноса. API-ключи надо заново ввести в защищённой форме серверного приложения. Не копируйте секреты из Sites в чат.

## Обслуживание

```sh
systemctl status marketflow --no-pager
journalctl -u marketflow -n 60 --no-pager
curl --fail http://127.0.0.1:3000/healthz
bash /root/marketflow-ubuntu/backup.sh
```

`backup.sh` использует SQLite backup API (без неконсистентного копирования WAL) и сохраняет базу вместе с ключом шифрования в `/var/backups/marketflow/`. Копия секретная, права 0600. Рекомендуется отдельная защищённая копия за пределами сервера. Удаление/перезапись рабочей базы и автоматическая очистка резервных копий не выполняются.

Для смены пароля в терминале сервера (без пароля в истории; все старые сессии будут отозваны):

```sh
read -r -s -p 'Новый пароль (12+ символов): ' marketflow_password; printf '\n'
printf '%s' "$marketflow_password" | /opt/marketflow/runtime/bin/node /opt/marketflow/app/server/admin.mjs password /var/lib/marketflow/config.json
unset marketflow_password
chown marketflow:marketflow /var/lib/marketflow/config.json
systemctl restart marketflow
```

Перед любой переустановкой сделайте резервную копию. Обычный повторный запуск установщика не перезаписывает существующую установку. Полная проверка целевой Ubuntu, сети, выдачи HTTPS-сертификата, systemd и входа с физических устройств возможна только после выполнения команд на сервере.
